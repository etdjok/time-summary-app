# 心光 v2.4.2 设计文档：独立文档导入与「文档库」

- 日期：2026-09-29
- 状态：已获用户批准，进入实现
- 目标版本：v2.4.2
- 涉及文件：api/server.js、src/lib/nutstore.ts、src/hooks/useSummaryStore.ts、src/types/index.ts、src/components/ImportExportModal.tsx、src/components/DocumentLibrary.tsx（新增）、src/pages/Home.tsx、src/components/Changelog.tsx、package.json

## 1. 背景

当前导入 .md/.txt 的行为是「逐行拆散、合并进分类文件」（ImportExportModal.handleImport → addEntry），且 loadEntries 会把服务端返回的所有 .md 一律逐行解析。结果：原文件从不落云，用户「导入的文件找不到」。此外服务端 /filesmd 只扫描 `''、/journal、/brain` 三个目录，响应中只有 `fileName + content`，没有目录信息，无法区分「独立文档」与「待拆散记录文件」。

## 2. 目标 / 非目标

目标：
1. .md/.markdown/.txt 导入支持「独立文档」模式（默认）：整篇原文保存到坚果云 `{basePath}/文档/` 下，保留原文件名与扩展名，重名自动加序号，绝不覆盖
2. 心光内新增「文档库」：列表 → 整篇阅读 → 整篇编辑（写回同一文件）→ 删除
3. 原「逐条导入到分类」保留，可在导入时切换
4. 加密链路（maybeEncrypt/maybeDecrypt）、条目日戳格式、五个既有视图、JSON 导入行为不变

非目标：不做全文搜索；不做多端冲突合并；不引入新依赖；不改密钥流程。

## 3. 方案（已选定）

- 存放：`{basePath}/文档/`（坚果云可见的独立文件夹）
- 识别：服务端 /filesmd 扫描新增 `'/文档'`，该目录文件响应带 `isDoc: true`
- 解析：客户端对 isDoc 文件整篇生成文档对象，不进入 entries 主数组
- 展示：首页右上新增「文档库」按钮（与导入/导出同区），全屏三态视图（列表/阅读/编辑）

## 4. 数据流

- 导入（独立文档模式）：选择文件 → writeDocument()（确保目录存在 → 冲突检测 → 加密 PUT 整篇原文）→ 刷新 loadEntries
- 加载：/filesmd（4 个目录）→ 分流：isDoc → documents（DocumentFile[]）；其余 → parseMarkdownFile → entries
- 文档库：store.documents → 列表 / 阅读（MarkdownPreview）/ 编辑（MarkdownEditor → writeFile 回写同一文件）/ 删除（deleteFile）

## 5. 逐文件改动

### 5.1 api/server.js
- parseWebDAVResponse：在 href 之外提取 `getlastmodified` / `getcontentlength`（位于 propstat.prop 内）；既有调用只取 href，不受影响
- listMdFilesInDir(username, password, encodedDirPath, extensions = ['.md'])：返回 `{ fileName, lastModified, size }[]`；扩展名可配置
- fetchMdContentsConcurrent：入参改为对象数组并透传元数据（原有 fileName/content 字段保持）
- /filesmd：扫描目录增加 `'/文档'`（扩展名 .md/.markdown/.txt）；仅该目录条目加 `isDoc: true`；根目录 EXCLUDED_ROOT_FILES 过滤适配新结构
- /list：新增可选 `extensions` 参数（缺省 ['.md']，行为不变）——供导入前冲突检测覆盖 .txt/.markdown

### 5.2 src/types/index.ts
- 新增 `DocumentFile { fileName; path; content; lastModified?; size? }`

### 5.3 src/lib/nutstore.ts
- loadEntries → 返回 `{ entries, documents }`；本地缓存结构同步升级为 `{ entries, documents }`，兼容读取旧数组缓存
- 新增 buildDocPath（`{basePath}/文档/{fileName}`）、pickDocFileName（重名自动 `名称(2).ext`）、writeDocument、ensureDocDir、listDocDir
- 复用 writeFile / readFile / deleteFile（加密自动适用）

### 5.4 src/hooks/useSummaryStore.ts
- state 增加 `documents: DocumentFile[]`；loadEntries 同时更新两者
- actions：updateDocumentContent(path, content)、removeDocumentByPath(path)
- entries 主流程零改动

### 5.5 src/components/ImportExportModal.tsx
- 模式切换：「独立文档（默认）」/「逐条导入到分类（原行为）」；独立文档模式隐藏分类选择器
- 独立文档：逐文件读取文本 → writeDocument（单文件失败不影响其他）→ 汇总提示 → 刷新
- 逐条模式与 JSON 分支保持原逻辑

### 5.6 src/components/DocumentLibrary.tsx（新增）
- 全屏三态：list / read / edit；列表按修改时间倒序（元数据缺失回退文件名排序，显示"—"）
- 阅读：MarkdownPreview 整篇渲染；编辑：MarkdownEditor 整篇编辑 → 保存 → writeFile 回写 → 更新 store
- 删除：确认后 deleteFile；空状态提供「去导入」

### 5.7 src/pages/Home.tsx
- 头部新增「文档库」按钮；渲染 DocumentLibrary；打开时触发一次 loadEntries 刷新

### 5.8 版本与更新日志
- package.json → 2.4.2；Changelog 顶部新增 v2.4.2 条目（仅加 2.4.2）

## 6. 边界与降级

- PROPFIND 元数据缺失 → 显示"—"、回退文件名排序
- 目录不存在 → /filesmd 静默返回空；写文档前先 mkdir（405 已存在视为成功）
- 重名 → 自动 `名称(2).ext`（基于实时目录列表 + 本批已用名）
- 单文件导入失败不影响批次其他文件；旧本地缓存（数组格式）自动兼容
- 大文件不做大小限制（后续如需再加护栏）

## 8. 验收标准

1. 独立文档模式导入 .md/.txt：坚果云《文档》出现同名文件，内容一字不差（加密开启时为密文）
2. 文档库：列表 → 整篇阅读 → 编辑保存 → 重新打开内容已更新；云端文件同步更新
3. 删除 → 云端文件消失
4. 逐条导入、JSON 导入回归一致；五视图（列表/四象限/热力图/打卡/AI）无文档内容混入
5. 加密开启/关闭两种状态全流程可用
6. 旧本地缓存（数组格式）升级不报错
